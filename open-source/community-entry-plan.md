# Community entry plan

**Status: Planned.** December 2026 targets preparation for a first January 2027
contribution. None of the actions below is claimed as completed.

## December checklist

- [ ] Read the contribution guide in the
      [vLLM repository](https://github.com/vllm-project/vllm).
- [ ] Study architecture using the repository and
      [official documentation](https://docs.vllm.ai/).
- [ ] Find and join appropriate community channels through official project
      links.
- [ ] Attend or review community meetings and record useful questions.
- [ ] Build locally or on suitable GPU infrastructure; record version and
      environment.
- [ ] Run applicable tests and official benchmarks; capture failures and
      constraints.
- [ ] Trace an inference request through the codebase and link relevant source
      revisions.
- [ ] Study recently merged pull requests for scope, tests and review
      expectations.
- [ ] Identify maintainers and subsystem owners through public project records.
- [ ] Reproduce at least one real issue and document a minimal reproduction.
- [ ] Write a technically useful issue comment with new evidence.
- [ ] Prepare a focused first contribution for January 2027.

## Choosing an entry issue

Look at documentation, testing, CI reliability, benchmark reliability,
observability, Docker, Kubernetes, API serving and error handling. Check whether
an issue is already being handled and clarify expected behaviour before coding.
Prefer a problem that can be reproduced and tested within available resources.

## Participation principles

Respect community time and contribution guidance. Read existing discussion,
share precise evidence and accept feedback. Do not send generic outreach or
claim ownership before agreement. Community acceptance cannot be guaranteed.

Record actual [investigations](issue-investigations/README.md) and
[contributions](contributions/README.md), distinguishing preparation, submission
and acceptance. See [Phase 3 onward](../ROADMAP.md).
